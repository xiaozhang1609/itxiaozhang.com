## 需求说明

一位经营副食品批发的老板，每天从个人微信的群聊、私聊中接收客户报货信息。这些报货消息数量多、格式乱，人工整理非常耗时。

现状：

- 客户主要发送文字，少量图片，偶尔语音。
- 商品名称、规格、数量、表达方式不统一。
- 同一个客户可能多次补充或修改订单。
- 不同客户有不同的商品习惯和价格规则。
- 老板每天花费约 5 小时人工整理、录单。

最终目标：在不改变客户现有微信使用习惯、不冒微信封号风险的情况下，尽可能自动完成订单整理、录入和打印。

需要区分两个概念：**数据能够方便地获取，不等于订单能够完整、及时、准确地处理**。后者才是需要重点解决的问题。

## 方案设计

经过测试，PC 微信的聊天记录能够一次性批量复制，并保留文字、图片，直接粘贴到 Word。基于这一点，可以停止研究微信 API、Hook、OCR 自动监控等高风险方案，把重心转向业务流程设计。整体流程如下：

1. **微信原生批量复制**：老板使用 PC 微信选择消息，复制文字和图片。
2. **保存原始 Word 文件**：按微信群 / 私聊、日期、批次归档。
3. **AI Agent + Skill + 知识库**：识别客户、商品、规格、数量、价格及订单修改。
4. **输出标准数据**：生成订单表格 + 需要人工确认的问题。
5. **导入专业软件并打印**：使用老板现有的业务系统。

建议保留 Word 作为原始数据格式，不需要额外转换为 TXT，也暂时不需要开发采集软件。但必须先验证所选 AI 工具能否正确读取 Word 中的图片及其上下文顺序。

## 实时性与批次处理

采集和处理频率应根据订单的实际履约要求确定，而不是为了自动化而追求实时。

| 模式   | 操作方式             | 适用情况      |
| ---- | ---------------- | --------- |
| 每日一次 | 下班前集中复制、AI 处理    | 次日配货、提前报单 |
| 定时批量 | 上午、中午、下午各处理一次    | 当天需要多次配货  |
| 紧急优先 | 普通订单批处理，急单人工即时处理 | 混合型批发业务   |
| 接近实时 | 频繁采集、立即处理        | 可能不适合当前方案 |

推荐「**紧急优先**」模式：普通订单批量处理，紧急订单人工优先。这样既能大幅减少重复劳动，又不需要为少数紧急订单投入复杂的微信自动监控系统。

如果老板要求所有订单在几分钟内完成处理，这套人工采集方案就无法充分满足要求，需要重新评估技术路线或安排专人值守。

## 订单处理中的关键问题

除了实时性，还有几个问题需要提前考虑，按重要程度排序如下。

| 问题        | 可能出现的情况                 | 建议             |
| --------- | ----------------------- | -------------- |
| 1. 订单重复   | 上午处理一次，下午又复制到上午的消息      | 记录已处理范围，建立去重机制 |
| 2. 订单修改   | 客户上午要 10 箱，下午改成 5 箱     | 识别修改关系，更新原订单   |
| 3. 身份识别   | 不同群里有同名客户               | 建立客户档案，不单凭昵称判断 |
| 4. 跨批次上下文 | 客户说「还是昨天那种」             | 保留历史订单与未完成事项   |
| 5. 信息准确性  | 商品规格不清楚、价格不确定           | AI 不猜测，输出待确认事项 |
| 6. 数据完整性  | 复制时漏选消息，或 Word 丢失发送人、时间 | 记录采集起止范围，抽样核对  |

还有一个容易忽略的问题：**订单什么时候算正式确定？** 例如客户上午报货，下午又改数量，而老板中午已经打印了单据。这个问题并非单纯依靠 AI 就能解决，而是需要明确订单的业务状态，例如「待确认、已确认、已导入、已打印、已修改」。

另外，可以引导客户尽量发送文字和图片，以降低语音识别成本。但既然原则是不增加客户负担，就不应假设所有客户一定遵守，偶发语音仍需要保留人工转写或确认的办法。

## 知识库与 Skill 的分工

知识库、Skill 与专业软件应严格分工：

- **知识库：负责提供业务事实。** 包括客户资料、商品编码、品牌规格、商品别名、单位换算、价格规则、历史订单。
- **Skill：负责规定处理方法。** 包括怎么读取 Word、区分不同客户、合并消息、识别修改、查询知识库、检查错误并输出订单。
- **专业软件：负责最终业务执行。** 导入准确的商品编码、数量、客户等字段，完成后续订单管理和打印。

知识库可以持续完善，但不能让 AI 在没有确认的情况下自动更改商品价格、客户资料或业务规则。

## 落地前需要确认的问题

以下问题会直接决定系统设计，需要先向老板确认。

| 需要确认                  | 为什么重要         |
| --------------------- | ------------- |
| 订单通常当天送货，还是第二天送货？     | 决定实时性要求       |
| 一天大概多少客户、多少微信群、多少条消息？ | 决定批次大小和操作成本   |
| 客户是否频繁修改、取消订单？        | 决定订单状态管理复杂度   |
| 同一客户是否同时通过群聊和私聊报货？    | 决定跨会话合并规则     |
| 老板当前使用什么进销存软件？        | 决定导出字段及导入方式   |
| 商品、客户和价格资料有没有现成表格？    | 决定知识库建设成本     |
| 能否允许少量不确定订单人工确认？      | 决定自动化可靠性边界    |
| 客户聊天信息能否交给云端 AI 处理？   | 决定隐私措施及模型部署方式 |

## 实现效果

这套方案的目标，是把老板每天约 5 小时的整理、录单时间砍掉一大半。对该方案的初步评估如下：

| 项目     | 评价             |
| ------ | -------------- |
| 技术可行性  | 较高             |
| 开发复杂度  | 低至中等，取决于业务规则   |
| 微信账号风险 | 较低，使用原生手工操作    |
| 订单准确性  | 需要实际样本验证       |
| 后期扩展性  | 良好             |

建议先不要立刻开发 Skill，而是用几天真实订单测试完整流程：批量复制到 Word、交给 AI 整理、人工核对、检查是否能导入专业软件。只要测试能够证明处理时间明显缩短、关键订单信息足够准确，再把成功的处理方法固定为 Skill。

真正需要确认的，不再是如何读取微信，而是**老板要求多快完成订单、订单变更有多频繁，以及现有专业软件能接受什么格式的数据**。这三个问题一旦弄清楚，就可以较准确地确定第一版应该做到什么程度，避免不必要的开发。
